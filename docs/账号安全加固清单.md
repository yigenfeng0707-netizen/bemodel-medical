## P0 · 立即执行（公网暴露的账号必须先处理）

### 1. 轮换所有账号密码（含已公开的 viewer）

- **操作**：在服务器/容器内生成 bcrypt 哈希后更新数据库，不要明文写库。

```bash
# 在 server 目录执行（复用项目依赖 bcryptjs，cost=12）
node -e "const b=require('bcryptjs');console.log(b.hashSync(process.argv[1],12))" '替换为你的强密码'
```

```sql
-- 逐个替换 <HASH>，只改需要保留的账号
UPDATE bm_user SET password_hash='<HASH>' WHERE username='admin';
UPDATE bm_user SET password_hash='<HASH>' WHERE username='modeler';
UPDATE bm_user SET password_hash='<HASH>' WHERE username='reviewer';
UPDATE bm_user SET password_hash='<HASH>' WHERE username='viewer';
```

- **注意**：种子是 `ON CONFLICT DO NOTHING`，重启不会把你的改动覆盖回去；但如果清空数据卷，会重新种子出默认密码 —— 清卷后必须重跑本节。
- **验证**：旧密码登录返回「用户名或密码错误」；新密码返回 token。

### 2. 删除或停用不需要对公网开放的账号

- **操作**（推荐：公网只留只读演示账号）：

```sql
-- 先确认没有业务依赖，再删除
DELETE FROM bm_user WHERE username IN ('admin','modeler','reviewer');
```

- 若必须保留管理账号，则改为「强随机密码 + 仅内网/白名单访问」，不要把密码写进任何文档或页面。
- **验证**：`SELECT username, role FROM bm_user;` 只剩预期账号。

### 3. 轮换 JWT_SECRET（强制所有旧会话失效）

- **操作**：在部署环境（空间 Secrets / docker-compose / RDS 参数）替换 `JWT_SECRET` 与 `APP_SECRET_KEY` 为 32 字节以上随机值，然后重启服务。

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

- **影响**：全员被登出，需要重新登录。
- **验证**：用轮换前拿到的 token 调 `GET /api/auth/me` 应返回 401。

### 4. 停止在任何日志/文档/页面中输出密码

- **页面**：介绍站已只保留 `viewer` 只读账号（如仍要更彻底，可整段删除）。
- **代码（已完成，待部署）**：`server/src/index.js` 已按 `config.isProd` 分支处理，生产启动日志不再打印演示账号密码。
- **文档**：README 的演示账号表如果仓库会公开，建议标注「仅本地演示环境」或移除密码列。
- **验证**：`grep -rn "admin123\|model123\|reviewer123" --exclude-dir=node_modules` 只应命中测试或演示说明。

### 5. 确认数据库与 MCP 的凭据强度

- `PG_PASSWORD`、`PG_USER` 不可用默认值 `bemodel/bemodel`；数据库端口不要映射到公网。
- `MCP_API_KEY` 已配置且为强随机；未配置时 `/mcp` 全拒，这是预期行为。
- 涉及库连接密码的字段是 AES-256-GCM 密文存储，确认 `APP_SECRET_KEY` 与之一同保管、可轮换。
- **验证**：不带 `X-Api-Key` 调 `POST /mcp` 应被拒绝。

### 6. 收紧传输与跨域

- 确认对外入口是 HTTPS（魔搭 `*.ms.show` 已由平台提供 TLS）。
- `CORS_ORIGINS` 只填实际使用域名，不填 `*`；生产默认为空即不放行跨域，除非确有前端分离部署。
- **验证**：从其他域名发起带 `Origin` 的请求，响应中不应出现允许该来源的 CORS 头。

## P1 · 一周内完成（提升抗爆破与可追溯性）

### 7. 增加账号维度锁定

- **状态（已落地，待部署）**：同用户名连续失败 5 次锁定 15 分钟，锁定期间正确密码也拒绝；与 IP 限流均为进程内计数，多实例不共享。
- **运维**：多实例部署时需把计数迁移到 Redis/PG 等共享存储。
- **验证**：连续 5 次错误密码后，第 6 次即使密码正确也提示锁定；已有自动化测试覆盖。

### 8. 登录审计留痕

- **状态（已落地，待部署）**：`bm_login_audit` 记录 username、IP、UA、结果和时间，成功、失败、锁定均留痕；重种子不会清空审计表。
- **运维**：90 天保留策略仍需配置定期清理/归档，当前代码不自动清理。
- **验证**：登录成功、失败与锁定均各产生一条记录；已有自动化测试覆盖。

### 9. 提高密码与哈希强度

- **状态（部分落地）**：种子账号的 bcrypt cost 已提高到 12；已有账号只有在轮换密码后才会使用新 cost。
- 密码策略：长度 ≥ 12、不得包含用户名、禁止使用 `admin123` 一类弱口令；当前无改密接口，通过 SQL 轮换时需人工执行该策略。
- 演示账号（如保留 viewer）与业务账号必须使用不同口令。

### 10. 缩短会话并支持主动失效

- **状态（部分落地，待部署）**：JWT TTL 已降为 2 小时，token 含 `jti`；`POST /api/auth/logout` 将当前 `jti` 加入服务端黑名单，前端登出已接入，服务端失败时也会清理本地凭据。
- **限制**：黑名单为进程内实现，多实例不共享；按用户批量失效（如改密后清除该用户全部会话）尚未实现，改密后仍需轮换 `JWT_SECRET` 强制旧会话全部失效。
- **验证**：登出后原 token 立即失效，重复登出返回 401，重新登录可正常使用；已有自动化测试覆盖。

### 11. 最小权限复核

- `REVIEWER` 只用于评审/发布审批（防自审），不应具备建模写权限。
- `VIEWER` 只读：抽测 `POST /api/domain`、`PUT /api/concept/*` 应返回 403。
- 只读型 POST 白名单（问数/搜索/探针执行）全角色可用属预期设计，但要确认其中没有副作用接口混入。
